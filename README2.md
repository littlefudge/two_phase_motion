# two_phase_motion: описание проекта

Проект численно исследует систему двухфазного гидродинамического движения в пространстве переменных `q1`, `q2`, `r`. Основная задача — для заданной трёхмерной сетки начальных точек решить систему вперёд и назад во времени и отнести каждую точку к одному из заранее определённых типов поведения траектории.

Расчёт распределяется между процессами OpenMPI, а результаты сохраняются отдельно для каждого ранга в каталоге `res`. Затем результаты объединяются и используются для построения карт классификации в различных сечениях фазового пространства.

## Основная процедура расчёта

`main_test_rk45.py` выполняет весь вычислительный цикл.

### Математическая модель

Для параметров системы `a`, `mu`, `tau` решаются уравнения:

```text
dq1/dt = q1 * (2*a^2*tau*q2 - mu*(q1-q2)*q1*r)
dq2/dt = (q1-q2)*r*(q1^2-a^2)
dr/dt  = tau*q2*r*(q1^2-a^2)
```

В программе та же система реализована в функции `hydro`, а её аналитический якобиан — в `hydroj`.

### Построение сетки

Параметры сетки задаются в `params.yaml`:

- `n_u`, `n_v`, `n_r` — число точек по `q1`, `q2`, `r`;
- `L_u0`/`L_u1`, `L_v0`/`L_v1`, `L_r0`/`L_r1` — границы сетки;
- `logu`, `logv`, `logr` — режим осей: линейная или десятичная логарифмическая сетка;
- `logall = 1` используется как дополнительный признак общей логарифмической записи;
- `logr = 10` поддерживает специальную сетку вокруг кривой особых точек.

Трёхмерная сетка сначала нумеруется линейным индексом. Функция `get_pos` возвращает трёхмерные индексы точки по этому номеру. Функция `get_share` делит все точки между MPI-процессами пропорционально рангу процесса.

### Интегрирование траектории

Для каждой начальной точки функция `solver` запускает `solve_ivp` методом `RK45`:

- вперёд от `t = 0` до `glob_right`;
- назад от `t = 0` до `glob_left`;
- с интервалами остановки и контролем особых событий;
- отдельно фиксируются конечные точки и моменты наступления событий.

Функции события отслеживают пересечения:

- `q1 = -a` и `q1 = a`;
- `q2 = -a` и `q2 = a`;
- `q2 = 0`;
- выход радиальной переменной за порог `r_inf`.

Функция `postproc` собирает из решения последние точки и времена наступления всех обнаруженных событий.

### Классификация точек

Начальная точка сначала относится к одной из областей относительно критической линии `q1 = a` и критического значения `q2 = a`. Затем функция соответствующего теста решает, в какую категорию её добавить:

| Класс | Интерпретация в коде |
|---|---|
| `red` | Красная область или тип по траектории в минус-направлении |
| `green` | Траектория достигает/пересекает отмеченное событие по `q2` |
| `blue` | Начальная точка относится к синему классу по критерию `q1` |
| `black` | Траектория попадает в другой режим относительно критической области |
| `white_0` | Конечная точка близка к особой линии и одновременно выполнено событие `q2 = 0` |
| `white_1` | Конечная точка близка к особой линии, но событие `q2 = 0` отсутствует |
| `smth` | Неоднозначный или не распознанный тип |

Классические области и точные условия приведены в `test1`–`test4`. Эти функции являются основным местом восстановления смысла классификации при работе с исторической версией проекта.

### Сохранение данных

Функция `writer` для каждого процесса создаёт:

- текстовые файлы `res/q1q2r_<класс>_<rank>.txt` с начальными координатами точек;
- бинарный файл `res/q1q2r_<rank>.pkl`, содержащий словарь с ключами классов.

Для каждой точки в словаре сохраняются начальная точка `init`, конечная точка при интегрировании вперёд `pend` и конечная точка при интегрировании назад `mend`.

Запись включена для формата, по умолчанию заданного параметром `saveto: './res'`.

## Конфигурация расчёта

Основные секции `params.yaml`:

- `equations` — текстовое напоминание о системе уравнений;
- `glob_left`, `glob_right` — границы интегрирования назад и вперёд;
- `solver` — тип метода и минимальный шаг;
- `zero`, `infty` — пороги окрестности нуля и бесконечности;
- `eps_w` — радиус окрестности особой линии;
- `delta_blue` — порог признака синего класса;
- `const` — значения `mu`, `tau`, `a`;
- параметры сетки `n_*`, `L_*`, `log*`;
- `saveto` — каталог результатов.

Текущий конфигурационный файл настроен на базовый набор параметров `mu = 4`, `tau = 1`, `a = 1` и сетку с логарифмическими координатами.

## Запуск на кластере

Цепочка запуска выглядит так:

```bash
qsub 00_pusk.sh
```

`00_pusk.sh` отправляет в PBS-систему задачу `01_run.sh`.

`01_run.sh`:

1. задаёт имя задачи, очередь, число узлов и время выполнения;
2. запускает `main_test_rk45.py` через `mpirun`;
3. передаёт каждому процессу информацию о ранге и размере сообщества через переменные OpenMPI `OMPI_COMM_WORLD_RANK` и `OMPI_COMM_WORLD_SIZE`.

Основной скрипт должен запускаться из каталога проекта, поскольку используется относительный путь `./params.yaml` и каталог `saveto`.

### Примечание о совместимости путей

В представленной версии скрипты содержат жёстко заданные серверные и старые локальные пути, например `/share/anaconda3/bin/python3`, `/home/panov/calc/python/...`, а plotter-файлы обращаются к каталогу `../../final_*`. Перед запуском у себя необходимо заменить эти пути на актуальные каталоги проекта и результатов.

## Объединение данных

`02_proc.sh` собирает текстовые выходные файлы по маскам имён:

- `*pp*.dat` в `res/pp.dat`;
- `*pm*.dat` в `res/pm.dat`;
- `*mp*.dat` в `res/mp.dat`;
- `*mm*.dat` в `res/mm.dat`;
- `*p5*.dat` в `res/p5.dat`.

Части скрипта с сортировкой закомментированы. Скрипт предполагает, что расчёт уже создал соответствующие `.dat`-файлы в каталоге `res`.

## Визуализация фазового пространства

Скрипты в `plotters/phase_space` читают параметры расчёта и объединяют все `q1q2r_*.pkl` через `pickle`, после чего строят сечения для фиксированных значений одной координаты.

- `plotter_q1q2.py` — проекция `q1`–`q2` с логарифмическими осями;
- `plotter_q1q2_lin.py` — линейная карта в плоскости `q1`–`q2`;
- `plotter_q1r.py` — логарифмическая плоскость `q1`–`r`;
- `plotter_q1r_lin.py` — линейная плоскость `q1`–`r`;
- `plotter_q1r_lin_log.py` — `q1` в линейном масштабе и `log10(r)` по вертикальной оси.

Для запуска нужно сначала настроить в каждом скрипте словарь `names`:

```python
names = {
    'params': 'путь/к/params.yaml',
    'result': 'путь/к/q1q2r_*.pkl',
    'frames': 'путь/для/сохранения/frame_{0:04d}'
}
```

Каждый скрипт проходит по сетке фиксированной координаты, создаёт кадр Matplotlib и сохраняет PNG-последовательность для последующего отчёта или анимации.

## Визуализация отдельных траекторий

`plotters/trajectories/trj_plotter_report.ipynb` содержит перенос основных процедур расчёта в интерактивный notebook. Он предназначен для подробного анализа одной начальной точки:

- конфигурирует параметры через `params.yaml`;
- решает систему вперёд и назад методом `RK45`;
- собирает точки остановки и особые события;
- выполняет ту же классификационную обработку;
- строит графики траектории в плоскостях `q1`–`r`, `q2`–`r` и других сочетаниях переменных.

Ноутбук удобно использовать для проверки гипотезы о конкретной точке до запуска расчёта всей сетки.

## Типичный рабочий цикл

1. Изменить параметры расчёта в `params.yaml`.
2. Настроить число узлов и процессов в `00_pusk.sh`/`01_run.sh`.
3. Отправить расчёт через `qsub`.
4. Проверить появление `q1q2r_<класс>_<rank>.txt` и `.pkl` в `res`.
5. При необходимости выполнить `02_proc.sh`.
6. Настроить путевые параметры нужного plotter-файла.
7. Построить PNG-кадры и собрать отдельную траекторию в notebook.
